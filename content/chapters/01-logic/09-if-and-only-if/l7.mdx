The **if-and-only-if statement** is defined by
$$
p \Leftrightarrow q \;:\equiv\; (p \Rightarrow q) \wedge (q \Rightarrow p),
$$

*Symbol by symbol: $\Leftrightarrow$ is "exactly when", $\Rightarrow$ is "forces", $\wedge$ is "and", $\equiv$ is "says the same as". So the line reads: *$p$ exactly when $q$* is defined to mean both directions at once: $p$ forces $q$, and $q$ forces $p$*

and read "$p$ if and only if $q$", abbreviated *iff*. Its truth table is T exactly where $p$ and $q$ agree:

Note the relationship to §1.3's $\equiv$: $p \equiv q$ holds exactly when $p \Leftrightarrow q$ is a tautology. The symbol $\Leftrightarrow$ is a joining word inside statements; $\equiv$ is an claim about statements. In practice this distinction is often elided, but it is why "$p \Leftrightarrow q$" can be false while "$\equiv$" claims never are.

Because the definition is a conjunction, **a proof of an if-and-only-if statement is two proofs**. The named move is **check both boxes**.

## The theorem

> **Theorem.** For all an integer $n$: $n$ is even $\iff$ $n^2$ is even.

<Discussion>
  <div slot="know">Definitions: $n$ even iff $\exists k \in \mathbb{Z},\, n = 2k$; $n$ odd iff $\exists k \in \mathbb{Z},\, n = 2k+1$; every integer is exactly one of the two (this is the division algorithm for $d = 2$, §4.4). Direction (forward) has a hypothesis that unfolds into a usable equation. Direction (backward) has hypothesis $n^2 = 2k$, from which no information about $n$ is extractable without inverting the squaring map.</div>
  <div slot="want">Both implications.</div>
  <div slot="how">(forward) directly. (backward) by contrapositive: prove $n$ odd $\Rightarrow n^2$ odd, whose hypothesis unfolds usefully.</div>
</Discussion>

<Proof>
(forward) Suppose $n$ is even. Then $n = 2k$ for some integer $k$, so $n^2 = 4k^2 = 2(2k^2)$. Since $2k^2$ is an integer, $n^2$ is even.

(backward) We prove the contrapositive: if $n$ is odd then $n^2$ is odd. Suppose $n = 2k+1$ with $k$ an integer. Then
$$
n^2 = 4k^2 + 4k + 1 = 2\big(2k^2 + 2k\big) + 1,
$$
and $2k^2 + 2k \in \mathbb{Z}$, so $n^2$ is odd. Since every integer is even or odd and not both, contraposition gives: $n^2$ even $\Rightarrow$ $n$ even.

Both implications hold, so the if-and-only-if statement.
</Proof>

Two observations. First, the directions required different methods — this is typical, and it is why the two halves must be written separately rather than merged into a chain. Second, the (backward) direction used the fact that every integer is even or odd and never both. That fact is not free; it is the $d=2$ case of the division algorithm, and a fully careful treatment proves it (§4.4) before using it here.

## Definitions go both ways, as a matter of definition

Every mathematical definition is an if-and-only-if statement, written with "if" by convention:

> $n$ is *even* **if** $n = 2k$ for some integer $k$.

means

> $n \text{ is even} \iff \exists k \in \mathbb{Z},\, n = 2k.$
>
> — *$n$ is even exactly when some whole number $k$ has $n = 2k$*

The consequence is practical: a definition may be used in **both directions**, and virtually every proof does. Unfolding ("$n$ is even, so write $n = 2k$") uses one; folding ("we have shown $n^2 = 2m$ with an integer $m$, so $n^2$ is even") uses the other. When a proof stalls, the first diagnostic is whether every definition in sight has been unfolded.

<Warning title="Iff-chains and reversibility">
A chain
$$
p \iff r_1 \iff r_2 \iff \cdots \iff q
$$

*Symbol by symbol: $\Leftrightarrow$ is "exactly when". So the line reads: $p$ holds exactly when $r_1$ does, which holds exactly when $r_2$ does, and so on down to $q$ — so $p$ and $q$ stand or fall together*

proves $p \iff q$ only if every link is genuinely an if-and-only-if statement. The failure mode is writing $\iff$ where only $\Rightarrow$ holds:

- $x = y \;\Rightarrow\; x^2 = y^2$, but not going the other way.
- $a = b \;\Rightarrow\; ac = bc$, and going the other way **only if** $c \neq 0$.
- $(x > 0) \wedge (y > 0) \;\Rightarrow\; xy > 0$, but not going the other way.

Solving equations is where this bites. "Solve $\sqrt{x+2} = x$" by squaring gives $x^2 - x - 2 = 0$, i.e. $x \in \{2, -1\}$ — but $x = -1$ fails the original. The squaring step was $\Rightarrow$, not $\iff$, so the final set is a superset of the solution set and must be filtered. Extraneous roots are exactly converse failures.
</Warning>

## Proving several statements equivalent

When three or more statements are to be shown pairwise equivalent, proving all $n(n-1)/2$ if-and-only-if statements separately is wasteful. Instead prove a **cycle** of implications:
$$
p \Rightarrow q \Rightarrow r \Rightarrow p.
$$

*Symbol by symbol: $\Rightarrow$ is "forces". So the line reads: $p$ forces $q$, which forces $r$, which forces $p$ again — and a loop like that makes all three equivalent, since you can travel from any one to any other*

Three implications rather than six, and every pairwise equivalence follows by composing around the cycle. Theorems of the form "the following are equivalent" — which you will meet constantly in later courses — are almost always proved this way, and choosing the cycle order so that each individual implication is easy is a real part of the work.

<Aside>
$p \Leftrightarrow q$ is also expressible as $\neg(p \oplus q)$, the negation of exclusive or, and as $(p \wedge q) \vee (\neg p \wedge \neg q)$. The first form is why $\Leftrightarrow$ is associative in a way that surprises people: $(p \Leftrightarrow q) \Leftrightarrow r$ and $p \Leftrightarrow (q \Leftrightarrow r)$ agree, both being true exactly when an even number of $p, q, r$ are false. Unlike $\Rightarrow$, the if-and-only-if statement chains associatively — but chained $\Leftrightarrow$ in mathematical writing means a conjunction of adjacent if-and-only-if statements, not iterated application, so do not rely on this.
</Aside>

<WhereThisGoes level="l7">

The two-direction habit is the shape of the structural theorems in both courses ahead of you.

**In calculus, the theorems worth remembering are the two-way ones.** *A graph is unbroken at a point exactly when the value it approaches there equals the value it takes.* Read one way it tells you what to check; read the other it tells you what you may then assume. A one-way theorem gives you half of that.

**Chains save work.** To prove $k$ statements all equivalent, proving every pair would take $k(k-1)$ implications. Proving a **cycle** — the first gives the second, the second the third, and the last gives the first back — takes $k$, and every pairwise equivalence follows by going round. Theorems phrased *the following are equivalent* are almost always proved this way, and choosing the order so each link is easy is a real part of the work.

**And definitions stay two-way.** A definition is a definition, usable in both directions without further argument — which is exactly why it is worth being clear whether the thing in front of you is a definition or a theorem.

</WhereThisGoes>
