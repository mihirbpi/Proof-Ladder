Module 1.12 taught you to prove a *for all* claim by taking any one case and following it. That works when all the cases are alike.

But some claims have cases that come **in order**, each one built from the one before. For those there is a better tool, and it is the subject of this chapter.

## The picture

Stand a hundred dominoes in a row and push the first. All hundred fall.

<Figure alt="A row of dominoes, the first three fallen and each tipping into the next, continuing to the right without end." caption="Two conditions — the first falls, and each reaches the next — force the whole row.">
  <DominoRow count={6} fallen={3} pushed={true} />
</Figure>

You pushed **one** domino. What made the rest fall was a relationship between neighbours: each one is close enough to knock over the next.

Two conditions, both needed:

1. **The first one falls.**
2. **Each one, if it falls, knocks over the next.**

Take away either and the argument collapses. Without the first, nothing ever starts. Without the second, the line stops at the first gap.

This is called **induction**, and the named move is **dominoes**.

## A pattern worth investigating

Add up odd numbers in order and watch what happens.

| How many odd numbers | The sum | |
|---|---|---|
| $1$ | $1$ | $= 1 \times 1$ |
| $2$ | $1+3 = 4$ | $= 2 \times 2$ |
| $3$ | $1+3+5 = 9$ | $= 3\times3$ |
| $4$ | $1+3+5+7=16$ | $=4\times4$ |
| $5$ | $1+3+5+7+9 = 25$ | $=5\times5$ |

Striking. Adding up the first few odd numbers seems to give a square number every time.

Now: **how would you ever be sure?**

You cannot check them all. The list of odd numbers never ends, so checking a hundred cases leaves infinitely many unchecked.

## Why checking is not enough

It is tempting to think a pattern holding for five cases, or five hundred, must hold forever. It does not follow, and mathematics has famous examples.

Take a counting number, multiply it by itself, add the number again, then add $41$. Start at $0$ and work up:
$$41, \quad 43, \quad 47, \quad 53, \quad 61, \quad 71, \quad \ldots$$

Every one of those is a **prime number**. It keeps working. Try $10$: you get $151$, prime. Try $20$: you get $461$, prime. Try $39$: you get $1601$, prime.

Forty cases in a row, all prime. Surely the pattern holds?

At $40$ you get $1681$, and $1681 = 41 \times 41$. **Not prime.**

The pattern breaks at exactly the point where anyone would have stopped checking.

<Warning title="Spotting is guessing">
Finding a pattern is how you *make a guess*. It is never how you *know*.

This is module 1.11's asymmetry again. A *for all* claim can be destroyed by one bad apple, and no number of confirmations can establish it. Only an argument covering all cases will do.
</Warning>

## What the dominoes give you

Here is the point. The odd-number pattern *can* be settled, and the domino argument is how.

**The first domino.** Take just the first odd number, $1$. Is it a square? Yes, $1 = 1 \times 1$. ✓

**Each knocks the next.** Suppose you have added up some run of odd numbers and got a square. What happens when you add the next odd number?

Picture the square built out of tiles. The next odd number is exactly the L-shaped strip you need to wrap around two sides to grow it into the next square up.

So a square plus the next odd number is the next square. ✓

Both conditions hold, so the claim is true for **every** run — not because we checked, but because the chain cannot break.

<Aside>
Notice carefully what the second condition said. It did **not** say "the pattern holds." It said "*if* it holds so far, *then* it holds one step further."

That is an if–then claim (module 1.5), and proving an if–then means assuming the *if* — which is why this is not circular reasoning. Module 6.2 makes this precise, because it is the point everybody worries about first.
</Aside>
