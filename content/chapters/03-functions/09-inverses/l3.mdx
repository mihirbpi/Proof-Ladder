Some functions can be run backwards. The backwards version is called the **inverse function**.

The question this module answers is: *when does an inverse exist?* And the answer is beautifully exact.

## Turning the arrows around

<Figure alt="Three elements on the left, each with one arrow, landing on three different elements on the right so that every one is used exactly once." caption="A bijection. Turn every arrow around and you get another function.">
  <ArrowDiagram labelLeft="S" labelRight="T"
    left={["a", "b", "c"]} right={["1", "2", "3"]}
    edges={[[0,1],[1,2],[2,0]]} />
</Figure>

Here $f(a) = 2$, $f(b) = 3$, $f(c) = 1$. Turn the arrows around:
$$
2 \to a, \qquad 3 \to b, \qquad 1 \to c.
$$

Every element of $T$ has exactly one arrow coming in, so when we reverse them, every element of $T$ has exactly one arrow going out — which is exactly what a function needs.

## Two ways it can go wrong

**If $f$ is not one-to-one**, some element of $T$ has *two* arrows coming in. Reversed, that element would have two arrows going out, and a function must give exactly one answer. Broken.

**If $f$ is not onto**, some element of $T$ has *no* arrows coming in. Reversed, that element would have no answer at all. But a function must work for everything in its domain. Broken.

So the two failure modes match the two properties exactly:

| For the backwards machine to be a function you need… | Which is… |
|---|---|
| every $t$ to have **at least** one answer | $f$ is **onto** |
| every $t$ to have **at most** one answer | $f$ is **one-to-one** |

## The theorem

> $f$ has an inverse function exactly when $f$ is a bijection.

That is a satisfying result. The two properties of the last three modules were not arbitrary — they are exactly the two halves of what it takes to run a function backwards. Onto gives you *an* answer; one-to-one gives you *only one*.

## Examples

**Doubling**, from whole numbers to even numbers. It is a bijection (module 3.8), so it has an inverse: halving. Check it — double $7$ to get $14$, then halve $14$ to get $7$. Back where you started.

**The alphabet function**, letters to $\{1, \ldots, 26\}$. A bijection, so its inverse exists: it takes a number and gives you the letter at that position. Feed it $3$ and out comes $\text{c}$.

**Round to the nearest ten**, whole numbers to whole numbers. Not one-to-one — $21$ and $24$ both give $20$ — so there is no way back: handed $20$, you cannot say what went in. No inverse.

**Multiplying a number by itself**, whole numbers to whole numbers. One-to-one, but not onto: nothing gives $2$. Shrink the target to $0, 1, 4, 9, 16, \ldots$ and it becomes a bijection, so the inverse exists — it has a name you meet in middle school, the square root.

## Undoing the undo

If $f$ is a bijection, then the backwards machine is a bijection too — and turning *its* arrows around gives you $f$ back.
Turning the arrows around twice puts them back the way they were.

<Warning title="Two different things are both written f⁻¹">
Module 3.3 traced back from a whole *set* — the **pre-image**. That exists for every function, no matter how messy.

This module runs the machine backwards on a single *element* — the **inverse function**. That exists only for bijections.

For *round to the nearest ten*, tracing back from the set $\{20\}$ gives $\{15, 16, \ldots, 24\}$ and makes perfect sense; asking for *the* single number that rounds to $20$ does not, because there are ten of them. Look at what is inside the brackets: a set means pre-image, an element means inverse function.
</Warning>

<Aside>
Every "undo" you know is an inverse function, and every one needs its domain trimmed to make it work. Multiplying a number by itself undoes with the square root — but, as above, only once the target is cut down to the numbers that really are somebody's square. Doubling undoes with halving — but on the whole numbers, only for the even ones. Those restrictions are not fussiness; they are exactly the trimming needed to make the original function a bijection.
</Aside>
