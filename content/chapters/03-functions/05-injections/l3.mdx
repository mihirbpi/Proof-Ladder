Every machine sends each input to exactly one output. But nothing stops two *different* inputs from landing on the same output. When that never happens, the machine is special.

A machine is **one-to-one** when different inputs always give different outputs.

## Two ways to say it

The natural way to say it is forwards:

> if two inputs are different, then their outputs are different.

But that is awkward to *use*, because it starts from two things being different, and "different" gives you nothing to work with.

So flip it around (module 1.7):

> if two inputs give the same output, then they were the same input all along.

Same statement, and this one is usable, because now you start from things being *equal*. This is the form to reach for in a proof, and the form worth memorizing.

## Checking examples

**The alphabet machine** — put in a letter, get its position. Different letters sit at different places, so nothing collides. One-to-one. ✓

**The last-digit machine** — put in a counting number, get its last digit. Put in $27$: you get $7$. Put in $17$: you also get $7$.

Two different inputs, one output. **Not** one-to-one. ✗

And notice how little work that took. One collision settles it, because "one-to-one" is a *for all* claim, and one bad apple destroys it (module 1.11).

**The doubling machine** — put in a counting number, get double. Is it one-to-one?

<Proof>
Take any two counting numbers whose doubles came out the same, and follow them.

If their doubles are the same, then halving those doubles gives the same answer too.

But halving a double gets you back to the number you started with.

So the two numbers you started with are the same number.

Different inputs could never have produced the same double. So doubling is one-to-one.
</Proof>

Look at the shape of that proof. It started from *the outputs are equal* and ended at *the inputs are equal* — exactly the flipped-around form. Every one-to-one proof looks like this.

## The picture test

For a machine you can graph, there is a quick check: draw **horizontal** lines across the graph. If any horizontal line hits the graph twice, then two inputs share an output, so the machine is not one-to-one.

<Warning title="Two different tests, two different lines">
The **vertical** line test asks whether something is a machine at all (module 3.1): one output per input.

The **horizontal** line test asks whether a machine is one-to-one: at most one input per output.

Different lines, different questions. Do not mix them up.
</Warning>

## Four machines, checked one at a time

The definition is short, so the way to get comfortable is to run it on examples.

**Doubling** — feed in a number, get twice it. One-to-one: proved above.

**Rounding to the nearest ten** — feed in a whole number, get back the nearest multiple of ten. **Not** one-to-one: $41$ and $44$ both come out as $40$. One pair of inputs sharing an output is enough to settle it, and you never need a second.

**Adding ten** — one-to-one. If two numbers come out equal, subtract ten from both and they were equal going in.

**"Which day of the week is it?"** — feed in a date, get back a day name. Badly not one-to-one: every Monday there has ever been shares an output. This machine is perfectly good at its job, and its job is precisely to collapse many inputs into few.

Notice the shape of the reasoning each time. To show a machine **is** one-to-one you have to argue about every possible pair at once. To show one **is not**, you produce two inputs and point.

<Aside>
Being one-to-one is exactly what module 3.3 called "tracing back never finds a crowd." Follow the arrows backwards from any output and you find one thing, or nothing — never two.

That is why one-to-one machines are the ones you have a hope of undoing, which is where module 3.9 is heading.
